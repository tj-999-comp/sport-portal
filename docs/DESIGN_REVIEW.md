# デザインレビューページ運用手順

対象ページ: `/design-review.html`

## 更新手順

1. STGで対象画面と変更範囲を確認する。
2. `app/design-review.html` の先頭へ新しい提案セクションを追加する。
3. 提案番号、対象バージョン、概要、比較案、採用案、採用理由、適用範囲を記載する。
4. 既存提案は削除せず、`details.proposal-history` の初期閉じ履歴へ移す。
5. 比較案は番号付きで並べ、通常・ホバー・フォーカス・選択・無効など必要な状態を操作できるようにする。
6. `app/design-review.js` と `app/design-review.css` を更新し、レビュー画面が本番APIやKVへアクセスしないことを確認する。
7. STGで受入チェックを行い、採用結果と対象コミットを作業記録および関連Issueへ残す。

## 提案記録テンプレート

各提案には次の項目を含める。

- 提案番号
- 対象バージョン
- 提案タイトルと概要
- 対象画面・対象部品
- 比較案と確認できる状態
- 採用・未採用・保留の状態
- 採用理由と適用範囲
- 関連Issue、対象コミット、確認日、確認者

## 受入チェック

- 最新提案がページ先頭に表示される。
- 過去提案が初期状態で閉じた履歴に残る。
- 採用案と採用理由が確認できる。
- 各比較案の選択・フォーカス表示が確認できる。
- アプリ本体との導線が動作する。
- スマートフォン、iPad、PC幅のFirefoxで横溢れ、リンク、履歴開閉、フォーカス表示を確認する。
- 未認証401、認証後200、HTTPS、`X-Robots-Tag`、robots metaを確認する。
- デザインレビュー画面から不要なAPI・KVアクセスが発生していない。

確認結果は、Issueコメントまたは作業記録に対象コミット、STG URL、確認日時、確認者、採用結果、既知の制約を記録する。認証情報は記録しない。
