# Bリーグページ 要件定義

## 1. 文書情報

- 作成日・公式情報確認日: 2026-09-24
- 状態: 要件確定（2026-09-24の利用者回答を反映）
- 親Issue: [#54 Bリーグ実装](https://github.com/tj-999-comp/sport-portal/issues/54)
- 対象URL: `/b-league/`
- 初期対象シーズン: 2026–27
- 今回の成果物: 要件定義と実装Issue。アプリ実装・デプロイは後続作業。

## 2. 目的と参照基準

JリーグページのJ1・J2・J3と同様に、Bプレミア・Bワン・Bネクストを切り替えて試合予定・確定結果を確認できるようにする。順位表はNPBページと同様の下部モーダルで、選択中カテゴリーの地区ごとに表示する。

| 項目 | 参照基準 |
| --- | --- |
| カテゴリー切替・選択状態 | `app/j-league/index.html`、`app/app.js` |
| 地区別順位表の縦並び | `app/npb.js` の `renderStandingsTable` / `renderStandingsLeagueTable` |
| 共通ヘッダー・ページ切替 | [Issue #52](https://github.com/tj-999-comp/sport-portal/issues/52)、[Issue #53](https://github.com/tj-999-comp/sport-portal/issues/53) |
| スワイプ・日付選択・スクロール | Jリーグ実装とIssue #53の確定方針 |
| 認証・運用・環境分離 | `docs/MVP_SPEC.md`、`DEPLOYMENT.md`、`docs/STG_DEPLOYMENT.md` |
| 競技別の外観 | 現在のBリーグ用白黒テーマ（`app/sport-themes.css`） |

古いNPB要件書にはセ・パ切替や星取表の記載があるが、現在の実装ではセ・パ順位表を縦に並べている。本要件では現在の表示を参照し、NPB固有の交流戦・CS・日本シリーズをBリーグへそのまま移植しない。既存の未コミット変更は参照にとどめ、本作業で変更しない。

## 3. 対象範囲

### 基本範囲

- Bプレミア・Bワン・Bネクストの3カテゴリー切替。
- 選択中カテゴリーのシーズン全体の試合予定・確定結果。
- 選択中カテゴリーの地区別順位表。
- 手動更新、自動更新、更新日時・成功／失敗状態。
- 既存の仮ページから実ページへの置き換えと既存ナビゲーションの維持。

### 追加範囲

- プレーオフ等の日程・結果・トーナメント表示。
- モーダル内の別タブにワイルドカード順位。
- Jリーグ同等の毎日5回の自動更新。

### 対象外

- 2025–26以前のB1・B2・B3、過去シーズンの選択、順位履歴。
- ライブスコア、クォーター別速報、プレー詳細、選手スタッツ。
- 天皇杯、オールスター、プレシーズン、国際大会、代表戦。
- 全クラブを単純に並べた全体順位の独立タブ、対戦成績の星取表、独自の順位計算・出場予測、通知機能。
- 会員登録、管理画面、リーグロゴ・クラブエンブレム・写真。

## 4. シーズンとカテゴリー

対象シーズンは2026–27とする。2026年と2027年の日程を同一シーズンとして扱い、暦年単位で取得を打ち切らない。自動的な次シーズン切替は今回含めない。

| タブ表示名 | 公式名称 | 地区構成 |
| --- | --- | --- |
| Bプレミア | B.LEAGUE PREMIER | 東地区・西地区 |
| Bワン | B.LEAGUE ONE | 北地区・東地区・中地区・西地区・南地区 |
| Bネクスト | B.LEAGUE NEXT | 1地区（順位表を1つ表示） |

地区構成は[公式の参入カテゴリー発表](https://www.bleague.jp/basketlive_news_detail/id%3D541287)と[Bネクスト大会方式の公式説明](https://www.bleague.jp/bmagazine/detail/id%3D543101)に基づく。所属・クラブ名・公式省略名は対象シーズンの最新公式情報を取得し、旧B1・B2・B3の所属を機械的に流用しない。

## 5. 共通画面と試合一覧

### 5.1 ナビゲーションとカテゴリー選択

- URLは `/b-league/` を維持する。トップの並びはJリーグ、NPB、Bリーグ、NBA。
- 左上の「スポーツポータル」からトップへ戻る。右上のページ選択はIssue #53に合わせ、トップを含めず各競技ページを並べる。
- 日付ナビ付近に「Bプレミア / Bワン / Bネクスト」のタブを配置する。初期選択はBプレミア。
- カテゴリー変更時は試合・日付候補・順位表・更新状態を一緒に切り替える。
- 同一ページ内ではカテゴリーごとに選択日を保持する。再読込後の保存は必須にしない。
- 読込中や高速なタブ切替でも、前カテゴリーの応答が現在の画面へ混入しない。
- シーズン、選択中カテゴリーが分かる見出し・ページタイトルを設定する。

### 5.2 日付別一覧

- 試合がある日だけ日付を並べる。左が過去、右が未来。
- 初期日は今日、今日に試合がなければ次の開催日。未来の日程がなければ最後の開催日。
- 日付ボタンと横スワイプを連動させる。同日の多数の試合は縦方向に確認できる。
- 縦スクロールと横スワイプの競合、モーダル背後へのスクロール漏れを防ぐ。
- 同日内は開始時刻順とし、時刻未定の試合は時刻確定済みの後に安定した順序で並べる。
- 空データ、読込中、公式未発表、取得失敗を区別して表示する。

### 5.3 試合カード

- 開始予定時刻／公式状態、ホーム（上段）・アウェイ（下段）の公式省略名、確定最終スコアを表示する。
- 会場名と公式の節／ラウンド名は取得できる場合に表示する。
- 開始時刻未定は「時刻未定」とし、0:00などに置き換えない。
- 開催前・試合中・終了・延期・中止・中断等を公式状態に合わせて扱う。試合中の現在スコアは出さない。
- 延長戦も確定最終スコアを表示し、延長表記は公式情報がある場合のみ付記する。
- 再試合・延期先は公式試合ID等で識別し、同じ対戦の別日開催を消したり、同一試合を重複表示したりしない。

## 6. 順位表

### 6.1 配置と操作

- 下部の順位ボタンから、背景を暗くした下部シート型モーダルを開く。
- ページで選択したカテゴリーの順位を表示し、見出しにもカテゴリー名を表示する。
- Bプレミアは東・西、Bワンは北・東・中・西・南の順に地区別の表を縦に並べる。Bネクストは1表。
- 閉じるボタン、背景クリック、Escapeで閉じられる。フォーカスをモーダル内に保ち、閉じたら元の操作箇所へ戻す。
- スマートフォンで基本の列を読めるように省略名・列幅を調整し、文字の極端な縮小や情報の切り捨てをしない。

### 6.2 基本表示項目

| 項目 | 扱い |
| --- | --- |
| 順位 | 公式順位・公式順序を維持する |
| クラブ名 | 対象シーズンの公式省略名 |
| 勝・敗 | レギュラーシーズンの公式値 |
| 勝率 | 公式値・公式精度を維持する |
| ゲーム差 | 公式値。先頭行や未発表値の記号も尊重する |
| 残試合数 | 公式値を優先。ない場合は公式で確認した予定試合数と消化試合数からのみ算出する |

NPBの引分列は追加しない。順位を勝率だけで独自に並べ替えない。未発表の順位・数値は「—」とし、行番号や0で埋めない。残試合数の算出根拠が不明な場合も「—」にする。予定試合数の変更・中止の扱いは公式に合わせる。

順位の取得元は[公式順位表](https://www.bleague.jp/standings/)。調査時には順位が「-」の行も確認できたため、順位が未確定の正常データを取得失敗と誤判定しない。

### 6.3 プレーオフ等

- モーダル内は「順位表」「ワイルドカード」「プレーオフ」の3タブとし、開くたびに「順位表」を初期表示する。全タブがページで選択中のカテゴリーに連動する。
- 日付別試合一覧にも対象カテゴリーのポストシーズンを含め、大会・ラウンドを区別する。
- トーナメントに対戦カード、各試合の予定・確定スコア、シリーズ勝敗、公式に確定した勝ち上がりを表示する。
- 未確定の出場クラブ・結果は未確定表示とし、順位から推測して埋めない。
- [2026–27公式フォーマット](https://www.bleague.jp/regulation/)では、Bプレミアは8クラブで準々決勝・準決勝が2勝先取、決勝が3勝先取。Bワンは16クラブで各ラウンド2勝先取。決勝会場の扱いもカテゴリーごとに異なる。
- 同ページでBネクストのプレーオフ規定は確認できなかった。大会がないカテゴリーに架空のトーナメントを作らない。実装時の最新公式発表で開催有無を確認する。
- Bネクストを含め、公式に大会が設定されていないカテゴリーの「プレーオフ」タブは「このカテゴリーにはプレーオフはありません」と表示する。公式未発表の場合は「公式情報未発表」、取得失敗は更新失敗として区別する。

### 6.4 ワイルドカード順位

- モーダル内の「ワイルドカード」タブに、選択中カテゴリーの公式ワイルドカード順位を表示する。地区別順位表へ混在させない。
- 列は「順位・クラブ名・勝・敗・勝率・ゲーム差・残試合数」を基本とする。ゲーム差はワイルドカード表の公式値を用い、地区別順位表の差を流用しない。
- Bプレミアは地区上位3クラブを除く対象、Bワンは地区上位2クラブを除く対象について、公式発表の順位・表示対象・順序を使う。出場枠はそれぞれ2枠・6枠。最新公式ルールが変わった場合は追随する。
- 全体の勝率順やプレーオフのシード順からワイルドカード順位を独自生成しない。出場確定表示も公式発表がある場合のみ付ける。
- 制度がないカテゴリーでは、タブ内に「このカテゴリーにはワイルドカードはありません」と表示する。
- 制度はあるが順位未発表の場合は「ワイルドカード順位は公式未発表」、取得失敗の場合は失敗状態と前回正常データを表示する。該当制度なしを取得失敗の代替にしない。

## 7. データ取得・更新

### 7.1 公式取得元と実装時の確認

- 日程・結果: [B.LEAGUE公式 日程・結果](https://www.bleague.jp/schedule/)
- 順位: [B.LEAGUE公式 順位表](https://www.bleague.jp/standings/)
- 大会方式: [B.LEAGUE公式 フォーマット](https://www.bleague.jp/regulation/)
- 年間日程の補助資料: [2026–27全カーディング発表](https://www.bleague.jp/basketlive_news_detail/id%3D548569)

3カテゴリーの入口・シーズン選択・日程と順位のページは確認済み。ただし、カテゴリーごとの取得パラメーター、全シーズンのページ分割、公開APIの有無、全項目の機械取得は未検証。実装の最初の工程で公式公開HTMLまたは公式ページが使用する公開データの取得方法を検証し、実データのfixtureと取得条件を記録する。未確認のAPIを存在するものとして設計しない。

取得元は公式に限定し、第三者サイトへ自動切替しない。公式側で未発表の情報と解析失敗を区別する。必要な取得が不可能な場合は原因と代替案をIssueに記録し、サンプルデータを本番の実結果として使用しない。

### 7.2 データの分離と保存

- 競技・カテゴリー・シーズンを識別できる構造とし、3カテゴリーの保存先を分離する。
- Jリーグ・NPBのAPI、データ、更新処理に混入させない。STGと本番のKVも既存の分離を維持する。
- 更新はカテゴリー単位で日程・結果・地区別順位・ワイルドカード順位・ポストシーズンを検証した後に保存する。
- 1カテゴリーの失敗が他カテゴリーの更新を止めず、前回正常データを上書きしない。
- 不正なシーズン・カテゴリー、重複試合、必須データの欠落、取得途中の一部ページだけのデータを検出する。
- 最新の正常データ取得日時と、直近の更新試行日時・成功／失敗を分けて扱う。
- 正常データがない場合は未取得表示。取得失敗後に以前のデータを表示する場合は、その旨と日時を表示する。
- APIパス・KVキーの具体名は実装設計で確定する。未知のカテゴリーはエラーにし、別カテゴリーへ黙って代替しない。

### 7.3 手動更新

- Jリーグ同様、選択中カテゴリーの日程・結果・地区別順位・ワイルドカード順位・ポストシーズンをまとめて更新する。
- 確認ダイアログ、更新中表示、二重実行防止、完了後の画面反映を設ける。
- カテゴリーを切り替えても進行中の更新結果が別カテゴリーへ表示されない。
- 自動更新と重なっても保存の整合性を維持する。

### 7.4 自動更新

- GitHub Actionsで専用の更新Workflowを実行し、WorkerのCron Triggerは使わない。
- 3カテゴリーとSTG／本番を独立して更新できる構成にする。既存Jリーグ・NPBの時刻は変えない。
- 手動実行でも環境・カテゴリーを選べるようにする。
- Jリーグと同じ毎日5回、17・19・21・22・23時JST（UTC 8・10・12・13・14時）に実行する。GitHub Actionsのスケジュール遅延は許容し、時刻どおりの更新完了を保証する仕様とはしない。
- 試合の有無にかかわらず実行し、HTTP応答だけでなく更新結果の成功状態を検証する。

## 8. 非機能要件と受入

- 日本語・日本時間、HTTPS、全URLとAPIへのBasic認証、検索エンジン非登録を維持する。
- iPhone・iPad・PCのFirefoxを主要対象とし、画面幅、タッチ、キーボード操作を検証する。
- 白黒のBリーグテーマと共通ヘッダーを維持し、選択状態を色だけで伝えない。
- Cloudflare Pages・Workers・KVとGitHub Actionsの既存構成／無料枠を前提に、全期間取得のリクエスト量・実行時間を実装時に確認する。

### 受け入れ条件

1. `/b-league/` の仮表示が置き換わり、トップ・各競技ページとの行き来ができる。
2. 3カテゴリーの切替が日程・結果・順位・更新状態に一貫して適用される。
3. 対象シーズンの2026年側と2027年側の日程を確認できる。
4. 今日／次の開催日／最終開催日の初期選択とカテゴリーごとの日付保持が動作する。
5. 予定時刻、未定、確定スコア、延期・中止等を区別でき、ライブスコアを表示しない。
6. 同日複数試合・連日同一カード・延期後の再設定で欠落や重複がない。
7. 選択カテゴリーの地区別順位表に順位・クラブ名・勝・敗・勝率・ゲーム差・残試合数を表示し、公式順序と未発表値を維持する。
8. 「順位表」「ワイルドカード」「プレーオフ」の別タブで選択中カテゴリーの情報を確認できる。ワイルドカードの対象・順序と、プレーオフの各試合・トーナメント・シリーズ勝敗が公式の確定状況に従う。該当大会・制度なし、未発表、取得失敗を区別する。
9. 手動更新と毎日17・19・21・22・23時JSTの自動更新が動作し、カテゴリー・環境が分離される。
10. 更新失敗時は前回正常データを保持し、初回未取得・公式未発表を区別できる。
11. 高速タブ切替や同時更新で他カテゴリーのデータが混ざらない。
12. 認証・noindex、モーダル操作、スクロール、端末幅、既存Jリーグ・NPBの回帰をSTGで確認する。

実装時は取得fixtureの単体テスト、APIの認証・保存・失敗ケース、ブラウザ操作を確認する。STG受入後の本番反映は既存の運用ルールに従う。

## 10. 確定事項と実装時の調査事項

2026-09-24の利用者回答により、以下を確定した。

1. 2026–27を対象に、プレーオフ等の日程・結果・トーナメントを含める。
2. 地区別順位を基本とし、ワイルドカード順位はモーダル内の別タブにする。
3. 自動更新はJリーグと同じ毎日5回（17・19・21・22・23時JST）にする。

利用者の判断を要する未確定要件はない。公式データの取得方法・提供範囲、特にワイルドカード順位とポストシーズンの機械取得は第7.1節に従って実装時に検証する。必要なデータが取得できない場合はその範囲を明示し、要件を黙って削除せずIssue上で相談する。
